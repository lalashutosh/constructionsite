# W3 · API additions and A2A shell (agent: integrator, branch w3/a2a, budget ~75 min)

**Gate:** Step 1 endpoints only for wow-engine functions that exist (31 may be skipped). Step 2 (A2A) only if the W2 gate is GO.

Mission: (1) expose the wow-engine functions through the HTTP API with the exact paths below (the UI is built against them in parallel); (2) wrap the service as an A2A agent so any other agent can ask Plumb; (3) time-boxed: if the A2A SDK fights you for more than 60 minutes, serve the agent card and one JSON-RPC method by hand and record why in `docs/decisions/a2a.md`.

Read first: `AGENTS.md`, `docs/handoff/integrator.md`, `api/main.py`. The wow-engine signatures are in `prompts/31_w3_wow_engine.md` (they may not be merged yet: import lazily and return HTTP 501 with a clear message until they exist; tests use fakes).
You own: `api/`, `a2a/`, `tests/test_api*`, `tests/test_a2a*`.

## Step 1 · endpoints (all JSON bodies are contract types or the wow-engine dataclasses serialised with pydantic/dataclasses.asdict)
- `POST /api/override` `{path, overrides:[...]}` -> recomputed `ProofObject`s for the last asked questions + `DoorRow`s (calls `engine.takeoff.overrides.apply`, then re-runs the cheap parts; extraction is cached).
- `GET /api/door-schedule?path=...&format=json|csv` -> rows, with `Content-Disposition` for csv.
- `POST /api/reconcile` multipart `{path, order_csv}` or JSON `{path, use_demo_order: true}` -> `ReconcileReport`.
- `POST /api/tamper` `{path, op}` -> `{label, facts_id}` (the synthetic revision is cached like any facts, flagged synthetic).
- `POST /api/delta` `{path, other_facts_id, vibe}` -> `DeltaReport`.
- `GET /api/trace/{request_id}` -> the stage timeline for the live reasoning view (same data as the SSE stream, stored for 10 minutes in memory).
Add them to the OpenAPI docs with examples. Keep CORS for localhost:5173.

## Step 2 · A2A (`a2a/`)
1. `.venv/bin/pip install "a2a-sdk[http-server]"`; read the INSTALLED package's samples and docstrings (`python -c "import a2a, pathlib; print(pathlib.Path(a2a.__file__).parent)"`). Do not hard-code method names or the agent-card path from memory: they changed between spec versions. The v0.3+ card is served at `/.well-known/agent-card.json`; verify against the installed SDK.
2. Agent card skills: `count_elements` (path + question -> ProofObject), `door_schedule` (path -> CSV artifact), `reconcile_order` (path + order CSV -> findings), `quote_with_decisions` (path + vibe or choices -> receipt). Card description in plain language: "Turns a drawing into numbers with a receipt: what was measured, assumed, chosen."
3. Map states: working while stages stream; `input-required` when a decision or the scale is needed (message = the cheapest question, with the options as structured data); completed with artifacts = ProofObject JSON (+ CSV for schedules). The agent that asks can answer the question and the task continues.
4. `python -m a2a.server` on port 9000. `python -m a2a.demo_client` is a second tiny agent (separate process) that asks "how many doors?" about a sample, receives `input-required` for the door width, answers "0.9", and prints the completed receipt. This is a video beat: "an agent hiring our agent".
5. The Skeptic never sees the Counter: the A2A layer must not leak voter outputs between voters.
