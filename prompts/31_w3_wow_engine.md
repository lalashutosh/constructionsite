# W3 · WOW ENGINE (agent: takeoff, branch w3/wow-engine, budget ~75 min)

**Run only if the W2 gate is GO.** Otherwise skip this prompt.

Mission: the three engine features that make a judge say "oh, that is a product": (1) the draft door schedule reconciled against an order, (2) a tamper test that shows consequences of a drawing change in order lines, (3) human overrides that flow into every dependent number. All pure functions with exact tests. Others (API, UI) call your signatures, so keep them EXACTLY as below.

You own: `engine/reconcile/`, `engine/takeoff/overrides.py`, `engine/takeoff/hardware.py`, `engine/decide/vibes/*.yaml` (hardware multipliers only), `tests/test_reconcile*.py`. Nothing else.

```python
#   findings are plain language: "14 doors ordered, 12 drawn: 2 ordered doors appear on no drawing", "Door D-07 ordered 0.9 m, drawn 0.8 m (relative width, scale not confirmed)".

# engine/reconcile/revision.py
def tamper(facts: SheetFacts, op: dict) -> tuple[SheetFacts, str]
#   op = {"type": "remove", "element_id": ...} | {"type": "add_door", "room_a": ..., "room_b": ..., "width_m": 0.9} | {"type": "widen", "element_id": ..., "factor": 1.1}
#   the returned label is ALWAYS "SYNTHETIC REVISION (generated by Plumb for demonstration)" and facts.provenance.revision = "synthetic-<n>"
def delta(a: SheetFacts, b: SheetFacts, vibe: str) -> DeltaReport
#   DeltaReport(doors, leaves, frames, hardware: list[OrderLine delta], area_m2 (with interval), paint_litres, findings: list[str], changed_element_ids)
```

## Steps
1. `DoorRow` matching: doors are matched between revisions by (rounded centre in px within tolerance 3% of image diagonal, same adjacent rooms). Document the tolerance and test it with a shifted copy.
2. Reconcile: match order lines to drawn doors by id when the order carries ids, otherwise by (room name or type, width within 5%), greedy with explicit ambiguity reporting — never silently pair. Unmatched on either side are listed.
3. Δ quantities: every delta line carries tags and uses the vibe's hardware multipliers; area deltas use `engine.takeoff.area` with intervals; if scale is door-prior-only, report deltas of COUNTS as exact and area/length deltas as relative with the reason.
4. A fixed demo scenario script `python -m engine.reconcile.demo` that builds from `contracts/fixtures/sample_facts.json`: draft door schedule -> demo order CSV generated with 2 doors missing from the drawing and 1 width mismatch (file `contracts/fixtures/demo_order.csv`, header comment: `# DEMO DATA generated for illustration`) -> reconcile findings -> tamper (remove one door) -> Δ report. Print all of it. This exact output feeds the video.
5. Property tests: `apply` is pure (input unchanged); `delta(a, a) == 0`; `delta(a, tamper(a, remove d))` has exactly -1 door, -1 leaf, -1 frame, -3 hinges for the standard vibe; reconcile is symmetric in the counts it reports; parse_order_csv handles `;` and `,` and decimal commas.
